Package Architecture

The core module implements CPU transforms. Optional Julia package extensions add GPU backends, MPI, automatic differentiation, and SIMD kernels.

Directory layout

SHTnsKit.jl/
  src/              Core module sources
  ext/              Package extensions (loaded when optional deps are present)
  docs/             Documenter.jl site you are reading now
  examples/         Runnable scripts (serial and MPI)
  benchmark/        Micro-benchmarks
  test/             Test suite
  Project.toml      Dependencies, extensions, compat bounds

How device dispatch works

The core implements analysis and synthesis for CPU arrays. Each GPU extension registers an adapter and adds methods for its own array types. Passing a device array selects that backend. With host inputs and several functional backends, pass a device array as the prototype to a typed GPU() call to select one. GPU Acceleration

Transform pipeline

Full-grid scalar transforms combine a longitude FFT with a latitude transform.

Analysis (spatial to spectral):

  1. FFT along longitude: f(theta, phi) becomes Fourier modes F_m(theta)
  2. Legendre integration along latitude: weighted sum of F_m * P_l^m yields a_lm

Synthesis (spectral to spatial):

  1. Legendre summation along latitude: a_lm * P_l^m accumulates into F_m(theta)
  2. Inverse FFT along longitude: Fourier modes become f(theta, phi)

The kernels.jl file contains the inlined per-latitude accumulation loops shared by scalar, vector, and QST transforms. Table-lookup kernels use precomputed P_l^m values; on-the-fly kernels recompute them via three-term recurrence.

Configuration lifecycle

SHTConfig is mutable and holds grid nodes, quadrature weights, normalization factors, and optional Legendre tables. Precomputed tables can dominate memory at high degree. Julia's garbage collector manages their lifetime.

Plans (SHTPlan, distributed plan types) hold mutable workspace including FFT plans and scratch buffers. Create one plan per simultaneously executing task.
